# 系统总览与架构设计

## 1. 项目概述

### 1.1 项目名称

**AI 数字员工平台（AI Digital Employee Platform — AiTaskOS）**

### 1.2 核心定位

构建一个"多租户、可审计的 AI 任务调度与执行编排平台"，同时内置初级产品经理级 BA 数字员工能力。平台负责任务图管理、数字员工（Agent）标准化接入与调度执行，通过统一协议与回调机制管理所有执行过程与结果。

### 1.3 核心能力

| 维度 | 能力项 |
|------|--------|
| BA 数字员工 | 需求理解、需求澄清、需求拆解、PRD 生成、流程设计、原型设计、需求评审、需求优化、存量系统升级设计 |
| 平台能力 | 任务管理、Agent 管理、调度编排、执行数据管理、审计与可观测 |
| 交互能力 | 实时交互、人机协同、局部修改、多轮迭代、知识沉淀 |

### 1.4 数字员工模型

```
数字员工 = Workflow（流程）
         + Agent（决策）
         + Skill（能力）
         + Knowledge（知识）
         + Memory（上下文）
         + Queue（指令队列）
```

### 2.2 核心设计原则

| 原则 | 说明 |
|------|------|
| 调度与执行分离 | 平台只负责调度编排，具体业务逻辑由 Agent 执行 |
| 协议标准化 | 所有 Agent 通过统一协议接入，支持同步/异步两种模式 |
| 数据统一 | 所有场景数据统一落到 DSL 结构化模型 |
| 实时可控 | 指令队列机制支持用户随时干预 AI 执行过程 |
| 知识分层 | 通用知识 → 项目知识 → 迭代知识，检索优先级逆序 |
| 全链路可观测 | 所有执行过程有日志、审计、追踪 |
| 开源可商用 | 所有组件均使用 Apache 2.0 / MIT / BSD 等开源许可 |

### 2.3 核心机制

#### 2.3.1 指令队列机制

```
用户操作 → 指令入队 → 优先级排序 → Agent 执行 → 局部更新 → DSL 同步
```

- 支持多条指令排队执行
- 支持优先级调度（high / normal / low）
- 支持中断当前流程
- 支持局部执行与增量更新

#### 2.3.2 Vibe PRD 双向同步

```
PRD ⇄ DSL ⇄ 原型
         ⇄ 流程图
```

通过 DSL 统一结构实现三者双向同步，修改任一资产自动传播到其他资产。

#### 2.3.3 异步反馈机制

```
AI 分析 → 发现问题 → 发送问题（Kafka） → 前端推送（SSE）→ 用户回答 → 自动修正
```

#### 2.3.4 迭代知识体系

```
检索优先级: 迭代知识 > 项目知识 > 通用知识

迭代知识: 当前迭代的需求、问题、产物、会议纪要
项目知识: 历史需求、系统文档、接口文档
通用知识: 模板、规范、行业标准
```

## 3. 系统边界

### 3.1 平台职责（✅ 必须实现）

| 职责 | 说明 |
|------|------|
| 任务管理 | 需求结构化 → Task Graph，任务 CRUD、依赖管理、状态流转 |
| Agent 管理 | Agent 注册/配置/启停，能力声明，多 Agent 调度 |
| 调度编排 | Task → Agent 匹配，DAG 执行，并发控制，重试机制 |
| 执行数据管理 | Agent 调用输入、执行过程数据（Streaming/Logs）、输出结果 |
| 审计与可观测 | 执行日志、操作审计、全链路追踪 |
| 指令队列 | 用户实时干预，优先级排队，局部执行 |
| DSL 管理 | 统一结构化数据模型，驱动 PRD/原型/流程图同步 |
| 知识管理 | 三层知识体系，向量化检索，知识沉淀 |

### 3.2 平台不负责（❌ 由外部 Agent 完成）

| 项目 | 说明 |
|------|------|
| 代码生成逻辑 | 由开发 Agent 完成 |
| 测试实现逻辑 | 由测试 Agent 完成 |
| 部署执行逻辑 | 由部署 Agent 完成 |
| Agent 内部决策 | Agent 自主决定执行策略 |
