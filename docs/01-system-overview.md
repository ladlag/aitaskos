# 系统总览与架构设计

## 1. 项目概述

### 1.1 项目名称

**AI 数字员工平台（AI Digital Employee Platform — AiTaskOS）**

### 1.2 核心定位

构建一个"多租户、可审计的 AI 任务调度与执行编排平台"。平台本身 **不包含任何业务 Agent**，而是作为 **数字员工管理 + 任务分配中枢**，负责：

- 定义和管理数字员工
- 将数字员工与外部 Agent 及工作流关联
- 提供任务输入、调度分配、获取输出（产出）
- 监控、审计、考核

所有 Agent（包括需求分析、PRD 生成、开发、测试等）均为 **外部独立服务**，可以是 Dify 创建的、第三方的、或自行开发的，但不会耦合到平台中。

### 1.3 核心能力

| 维度 | 能力项 |
|------|--------|
| 数字员工管理 | 数字员工定义、角色配置、Agent 绑定、工作流关联、能力声明 |
| 任务管理 | 任务创建、Task Graph、依赖管理、状态流转、优先级调度 |
| 调度编排 | Task → Agent 匹配、DAG 执行、指令队列、并发控制 |
| 平台能力 | 输入管理、输出收集、执行数据管理、文件解析 |
| 监控考核 | 执行日志、操作审计、全链路追踪、绩效统计 |
| 交互能力 | 实时交互、人机协同、局部修改、多轮迭代、知识沉淀 |

### 1.4 数字员工模型

数字员工是平台中的一等实体，它是 Agent + 工作流 + 知识 的组合配置：

```
数字员工 (Digital Employee)
  = 角色定义（Role）        ← 平台定义：BA、开发、测试、运维...
  + Agent 绑定（Agent[]）   ← 外部 Agent：Dify / 第三方 / 自建
  + Workflow（流程）         ← 工作流模板：任务执行的 DAG 编排
  + Knowledge（知识）       ← 关联的知识库
  + Memory（上下文）        ← 项目/迭代上下文
  + Queue（指令队列）       ← 接收的任务指令
```

### 1.5 平台与 Agent 的本质关系

```
❗ 关键边界:
  平台 = "调度中枢"（管人、派活、收结果、打分）
  Agent = "执行单元"（接活、干活、交结果）

  平台不参与具体业务产出，所有业务逻辑由外部 Agent 完成。
```

### 2.2 核心设计原则

| 原则 | 说明 |
|------|------|
| 调度与执行分离 | 平台只负责调度编排与数字员工管理，所有业务逻辑由外部 Agent 执行 |
| 协议标准化 | 所有 Agent 通过统一协议接入，支持同步/异步两种模式 |
| 数据统一 | 所有场景数据统一落到 DSL 结构化模型 |
| 实时可控 | 指令队列机制支持用户随时干预 AI 执行过程 |
| 知识分层 | 通用知识 → 项目知识 → 迭代知识，检索优先级逆序 |
| 全链路可观测 | 所有执行过程有日志、审计、追踪 |
| 开源可商用 | 所有组件均使用 Apache 2.0 / MIT / BSD 等开源许可 |

### 2.3 核心机制

#### 2.3.1 指令队列机制

```
用户操作 → 指令入队 → 优先级排序 → Agent 执行 → 局部更新 → DSL 同步
```

- 支持多条指令排队执行
- 支持优先级调度（high / normal / low）
- 支持中断当前流程
- 支持局部执行与增量更新

#### 2.3.2 Vibe PRD 双向同步

```
PRD ⇄ DSL ⇄ 原型
         ⇄ 流程图
```

通过 DSL 统一结构实现三者双向同步，修改任一资产自动传播到其他资产。

#### 2.3.3 异步反馈机制

```
AI 分析 → 发现问题 → 发送问题（Kafka） → 前端推送（SSE）→ 用户回答 → 自动修正
```

#### 2.3.4 迭代知识体系

```
检索优先级: 迭代知识 > 项目知识 > 通用知识

迭代知识: 当前迭代的需求、问题、产物、会议纪要
项目知识: 历史需求、系统文档、接口文档
通用知识: 模板、规范、行业标准
```

## 3. 系统边界

### 3.1 平台职责（✅ 必须实现）

| 职责 | 说明 |
|------|------|
| 数字员工管理 | 数字员工定义/配置/启停，角色管理，Agent 绑定，工作流关联 |
| 任务管理 | 需求结构化 → Task Graph，任务 CRUD、依赖管理、状态流转 |
| Agent 注册 | 外部 Agent 注册/配置/启停，能力声明，健康检查 |
| 调度编排 | Task → 数字员工 → Agent 匹配，DAG 执行，并发控制，重试机制 |
| 输入管理 | 接收用户输入，文件解析，数据预处理，提供给 Agent |
| 输出管理 | 接收 Agent 执行结果（产出/制品），存储与展示 |
| 执行数据管理 | Agent 调用输入、执行过程数据（Streaming/Logs）、输出结果 |
| 审计与可观测 | 执行日志、操作审计、全链路追踪 |
| 考核与统计 | 数字员工绩效统计、任务完成率、质量评分 |
| 指令队列 | 用户实时干预，优先级排队，局部执行 |
| DSL 管理 | 统一结构化数据模型，驱动 PRD/原型/流程图同步 |
| 知识管理 | 三层知识体系，向量化检索，知识沉淀 |

### 3.2 平台不负责（❌ 由外部 Agent 完成）

| 项目 | 说明 |
|------|------|
| 需求分析逻辑 | 由需求分析 Agent 完成（外部） |
| PRD 生成逻辑 | 由 PRD 生成 Agent 完成（外部） |
| 流程设计逻辑 | 由流程设计 Agent 完成（外部） |
| 代码生成逻辑 | 由开发 Agent 完成（外部） |
| 测试实现逻辑 | 由测试 Agent 完成（外部） |
| 部署执行逻辑 | 由部署 Agent 完成（外部） |
| Agent 内部决策 | Agent 自主决定执行策略 |

> **核心原则**：所有业务相关的 Agent（需求、开发、测试、部署等）都是外部独立服务，与平台完全解耦。平台仅负责"管人（数字员工）、派活（调度）、收结果（输出）、打分（考核）"。
